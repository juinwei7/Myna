# 專案憲法

九官鳥採 **SDD（規格驅動開發）**：先寫規格，再照規格實作，最後對規格驗收。
每份 spec 都要遵守以下原則；跟原則衝突的設計，要在該 spec 裡標示例外並說明理由。

每個功能一個資料夾，內含 `spec.md`（要解決什麼）、`plan.md`（怎麼做）、`tasks.md`（拆解與進度）、
`acceptance.md`（可執行的驗收）。

---

## 一、架構原則

### A1 — 決定要做什麼的邏輯留在 Python 後端
模型能力判斷、請求解析與驗證、排隊、下載、紀錄都在 `studio/`。
原生 app 只是介面：負責顯示，以及 Mac 才有的事（錄音、播放、垃圾桶、Finder、Dock、服務選單）。
**為什麼**：原生 app 與 MCP 兩個入口共用同一套規則，寫兩次就會分岔。
沒有網頁介面（2026-11-18 拿掉：功能 app 都有了）；連接埠只給 app 的 REST 與 MCP 用。

### A2 — 模型能力由目錄宣告
每個模型能做什麼（仿聲、內建配音員、聲音描述、語氣指令、原生語速）寫在 `catalog.py` 的資料裡，
介面與驗證都從這份資料推導，不在各處寫 `if model == ...`。
新增模型＝目錄加一筆；只有遇到新的模型家族才需要多寫一個轉接器。

### A3 — 設定可用環境變數覆寫
資料夾（`VOICE_STUDIO_HOME`，預設 `~/Library/Application Support/VoiceStudio`）、連接埠（`VOICE_STUDIO_PORT`）、
模型快取（`HF_HUB_CACHE`）都能覆寫。
**為什麼**：測試要指向臨時資料夾，不能碰到使用者真正的聲音與音檔。

### A4 — MLX 一次只跑一件
所有推論走同一條工作執行緒依序處理；模型下載走子程序（才能取消，也不會卡住推論）。

### A5 — 只用鎖定的依賴
後端依賴以 `mac/requirements.lock` 為準，app 內附同一組。
需要額外套件才能跑的模型（例如 Kokoro 要 `misaki`）不進目錄。
**為什麼**：app 要能整包帶走；也不擅自改使用者的環境。

### A6 — 向下相容
既有的聲音代號（`clone:<名稱>`、`preset:<配音員>`、`design`）、MCP 工具名稱與參數、
REST 路徑不得改壞；新增的是**擴充**，不是取代。
**為什麼**：已經有 AI 工具（經 MCP）在呼叫這些工具，改名或改參數會讓它們的呼叫失敗。

## 二、介面原則（macOS）

### U1 — 遵循 macOS 人機介面準則
完整選單列、每個動作都有快捷鍵、右鍵選單、拖放、空白鍵播放、Delete 刪除且能 ⌘Z 復原、
側欄可收合、視窗可自由縮放。參考 `macos-design-guidelines` skill 的檢查表。

### U2 — 視覺 token 集中在 `Theme.swift`
品牌色只有兩個，都有淺色與深色兩組值：**柿橘**（主要動作、播放中、波形已播放的部分，跟圖示同色系）、
**琥珀**（要注意的事）。其他一律用語意色（`.secondary`、`Color(nsColor:)`），不在各個 View 裡寫色碼。
內容頁的標題與段落標題用宋體，讓稿子、聲音、模型讀起來像一份文件；介面文字用系統字型。

### U3 — 回饋的份量要跟事情的份量相當
例行動作用行內回饋（列內進度、狀態文字）；模態對話框只留給不可復原的動作（例如刪除模型檔案）。

### U4 — 台灣用語、繁體中文
介面文字不夾英文（模型名稱、授權名稱等專有名詞除外）。

### U5 — 只有圖示的按鈕都要有說明
`accessibilityLabel` 給旁白，`help` 給滑鼠停留提示。

### U6 — 長工作看得到進度、可以取消
產生音檔、下載模型都要顯示進度，並且能中途取消。

### U7 — 清單（List、Table）的列裡不放按鈕
macOS 的清單背後是表格，列裡有 SwiftUI 的點擊會讓整張表的點擊被延後，嚴重時卡到下一次按滑鼠。
列上的動作走選取＋鍵盤、按兩下、右鍵選單；要有按鈕的列就不用清單，自己排（側欄、稿子的版本都是這樣做）。

### U8 — 次要動作用文字樣式
內容頁標題下方的動作（試聽、用這份稿子、在 Finder 中顯示）是主色的字加小圖示，不排成一整列按鈕；
整頁只有一個主要按鈕（產生音檔）。

## 三、測試原則

### C1 — Python 用標準庫 `unittest`，Swift 用 `swift test`
跑法（在專案根目錄）：`.venv/bin/python -m unittest discover -s studio/tests -t .`；
Swift 的可測邏輯放在 `VoiceStudioCore`，`cd mac && swift test`。

### C2 — 測試用臨時資料夾與假引擎
不載入真模型、不碰正式資料夾。真模型的驗證列為「慢速測試」，設 `VOICE_STUDIO_SLOW=1` 才跑。

### C3 — 每份 spec 的驗收條件都要能執行
`acceptance.md` 的每一條都對應一個測試或指令，不接受「看起來正常」。
需要人眼判斷的介面項目，用截圖存證並寫明檢查點。

## 五、安全與授權

### E1 — 只綁 `127.0.0.1`
### E2 — 檔案路徑限制在資料夾內
讀音檔、還原紀錄、刪除聲音都要檢查解析後的路徑仍在對應資料夾裡。
### E3 — 使用者資料不外傳
只有下載模型會連到 Hugging Face；稿子、錄音、成品都留在本機。
### E4 — 授權要標清楚
目錄寫明每個模型的授權與能不能商用；不能商用的模型在介面上要看得出來。
