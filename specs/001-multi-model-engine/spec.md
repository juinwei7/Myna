# Spec 001 — 多模型引擎

| | |
|---|---|
| 狀態 | 已完成（2026-11-18；快速測試 56 個、真模型 11 種組合都過） |
| 前置 | 現有語音服務（`studio/app.py`，只綁 Qwen3-TTS 三個模型） |
| 後續 | [Spec 002](../002-mac-app-redesign/spec.md)（原生介面重構） |

---

## 1. 問題

語音服務目前把三個 Qwen3-TTS 模型寫死在程式裡，「聲音」和「模型」綁在一起：
選 `clone:tw-female` 就一定是 1.7B Base，選 `preset:Vivian` 就一定是 CustomVoice。

實際用起來卡在三個地方：

1. **沒辦法換模型比較**：同一個台灣女聲，Qwen3 唸起來偏快，想試別家模型（VoxCPM2、Breeze）卻沒有入口。
2. **模型要自己去命令列下載**：不知道有哪些能用、多大、能不能商用，下載也看不到進度。
3. **記憶體只進不出**：模型載入後就一直佔著，模型一多就會把 48 GB 吃光。

## 2. 目標

把「聲音」和「模型」拆開，讓任何支援仿聲的模型都能用聲音庫裡的聲音，
並讓模型的下載、載入、卸載、刪除都由語音服務管理。

### 範圍內

- **模型目錄**：精選、實測過能唸中文的模型，標明能力、大小、授權
- **模型生命週期**：下載（看得到進度、可取消）、刪除、載入、卸載、記憶體上限自動卸載
- **統一的產生流程**：分段、套發音字典、段落停頓、進度回報、可取消
- **排隊與批次**：可以連續送出多筆；同一份稿子一次交給多個模型比較
- **把產出存成聲音**：聲音描述每次產生的音色都不同，滿意的那次可以直接存進聲音庫
- **自訂模型**：輸入 Hugging Face 上的模型名稱加入；限已有轉接器的模型家族
- **API 與 MCP 擴充**：新增模型相關端點與 `list_models` 工具，`synthesize` 可指定模型

### 範圍外

- 需要額外套件的模型（Kokoro、Spark-TTS）——違反憲法 A5
- 串流播放（邊產生邊播）——等介面重構後再評估
- 模型微調、訓練

## 3. 約束

### C-1 舊呼叫照常運作（憲法 A6）
`synthesize(text, voice="clone:tw-female")` 這種舊呼叫，不帶 `model` 也要照舊產生，
預設模型跟現在一樣（仿聲用 Qwen3 1.7B Base、配音員用 CustomVoice、描述用 VoiceDesign）。

### C-2 單一推論執行緒（憲法 A4）
下載可以跟產生同時進行；推論永遠一次一件。

### C-3 MCP 單次呼叫 15 秒內回應
MCP 的呼叫端（或中間的閘道）常見的逾時是 20～30 秒，`synthesize` 與 `get_job` 最多等 15 秒，沒做完就回 `job_id`。

### C-4 不新增依賴（憲法 A5）
只用 `requirements.lock` 裡已有的套件。

### C-5 下載與刪除只動自己那份模型
刪除模型只刪 Hugging Face 快取中那個模型的資料夾，不碰其他模型或使用者檔案。

## 4. 使用者故事

1. **換模型試同一個聲音**：我選台灣女聲，把模型從 Qwen3 換成 VoxCPM2，再產生一次比較。
2. **一次比較多個模型**：同一份稿子勾三個模型，一次排進佇列，做完逐一試聽。
3. **知道模型的底細**：下載前就看得到大小、語言、授權、能不能商用。
4. **下載看得到進度**：4 GB 的模型下載到一半想取消，可以取消。
5. **不怕記憶體爆掉**：模型超過記憶體上限時，最久沒用的自動卸載。
6. **描述出好聲音就留下來**：用聲音描述試到滿意的音色，把那次成品存成聲音庫裡的聲音。
7. **長稿子看得到進度**：一篇五段的稿子，看得到「第 3／5 段」，中途可以取消。
8. **Claude 也能選模型**：在 Claude 裡呼叫 `list_models` 看有哪些，`synthesize` 指定模型。
